# Why this repo exists

This is **Tiangolo's Full Stack FastAPI Template**: a complete, deployable app you copy to start a real product. It is not a library. It is a working dashboard with two durable nouns — **User** and **Item** — plus the auth, email, admin, tests, and Docker/CI you would otherwise rebuild.

**Product job:** let a site have accounts, let those accounts create and edit titled records ("items"), and let an operator (superuser) manage who is allowed in.

The workspace folder is named `read_status_and_bookmark`. That is assignment context. **Read status and bookmarks are not implemented.** Items today are a generic title + description owned by a user. Bookmarking or "I've read this" would be new fields or tables on top of this skeleton.

## What a person can do

1. **Join or be invited** — self-signup (`POST /users/signup`) or an admin creates the account and optionally emails credentials.
2. **Sign in** — email + password become a JWT stored by the SPA. Inactive users are blocked.
3. **Recover access** — request a reset email (always the same success copy, to avoid email enumeration), then set a new password with the token.
4. **Land on a dashboard** — greeting only; navigation lives in the sidebar.
5. **Work with items** — anyone logged in can list all items and create one. Update/delete is owner or superuser.
6. **Manage self** — name, email, password, or delete own account (superusers cannot self-delete).
7. **Administer users** — superusers only: list, create, edit flags (active / superuser), delete others.

Unauthenticated routes: login, signup, recover password, reset password. Everything under `/_layout` redirects to login if there is no token.

## Stack shape

- **Backend:** FastAPI + SQLModel + PostgreSQL. API prefix `/api/v1`. OpenAPI drives a generated TypeScript client.
- **Frontend:** React, Vite, TanStack Router/Query, Tailwind, shadcn. Built into `backend/app/frontend` and served by FastAPI on the same origin in production.
- **Email:** React Email templates + SMTP (Mailpit locally) for password reset and new-account mail.
- **Ops:** Docker Compose, Traefik, GitHub Actions, optional FastAPI Cloud.

## 1. Data model — User and Item

Source: `backend/app/models.py`

Two tables. A user owns many items; deleting a user cascades items. Passwords are stored hashed only. API DTOs (`UserPublic`, `ItemPublic`, `Token`, …) sit in the same file so OpenAPI stays in one place.

`ItemPublic.creator` is not a column: it is derived from the owner's name or email when serializing.

## 2. Auth API — get a session, recover it

Source: `backend/app/api/routes/login.py`

**Purpose:** prove identity and mint a short-lived JWT so the SPA can call the rest of `/api/v1`. Also the forgotten-password path without leaking whether an email exists.

<Endpoint id="ep-login" method="POST" path="/api/v1/login/access-token" summary="Exchange email+password for a bearer JWT" auth="None (OAuth2 password form). username field is the email." request={{ contentType: "application/x-www-form-urlencoded", example: "username=a@b.com&password=secret123" }} responses={[{ status: "200", description: "Token", example: "{\"access_token\":\"…\",\"token_type\":\"bearer\"}" }, { status: "400", description: "Wrong credentials or inactive user" }]}>

Inactive accounts fail here, not later. Token TTL is `ACCESS_TOKEN_EXPIRE_MINUTES`.

</Endpoint>

<Endpoint id="ep-recover" method="POST" path="/api/v1/password-recovery/{email}" summary="Send reset mail if the address exists; always the same message" auth="None" responses={[{ status: "200", description: "Generic success copy" }]}>

Prevents email enumeration. Real send only when `crud.get_user_by_email` finds a row.

</Endpoint>

<Endpoint id="ep-reset" method="POST" path="/api/v1/reset-password/" summary="Set a new password using the emailed token" auth="None (token in body)" request={{ contentType: "application/json", example: "{\"token\":\"…\",\"new_password\":\"newpass12\"}" }} responses={[{ status: "200", description: "Password updated" }, { status: "400", description: "Invalid token or inactive user" }]} />

## 3. Users API — join, self-serve, operate

Source: `backend/app/api/routes/users.py`

**Purpose:** create and mutate accounts. Split into three jobs: public signup, authenticated "me", superuser directory.

<Endpoint id="ep-signup" method="POST" path="/api/v1/users/signup" summary="Self-register a normal (non-superuser) account" auth="None" request={{ contentType: "application/json", example: "{\"email\":\"a@b.com\",\"password\":\"secret123\",\"full_name\":\"Ada\"}" }} responses={[{ status: "200", description: "UserPublic" }, { status: "400", description: "Email already exists" }]} />

<Endpoint id="ep-me" method="GET" path="/api/v1/users/me" summary="Who am I — drives sidebar Admin link and settings" auth="Bearer JWT" responses={[{ status: "200", description: "UserPublic including is_superuser / is_active" }]} />

<Endpoint id="ep-users-list" method="GET" path="/api/v1/users/" summary="Paginated user directory" auth="Bearer JWT + must be active superuser" params={[{ name: "skip", in: "query", type: "int" }, { name: "limit", in: "query", type: "int" }]} responses={[{ status: "200", description: "UsersPublic { data, count }" }]} />

Related: `PATCH /users/me`, `PATCH /users/me/password`, `DELETE /users/me` (blocked for superusers), admin `POST /users/`, `PATCH /users/{id}`, `DELETE /users/{id}`.

## Flows as jobs (end to end)

| Flow | Actor | Meant to do |
| --- | --- | --- |
| Signup | Anyone | Create a member account so they can receive a JWT later. |
| Login | Member | Prove password, store JWT, enter the shell. |
| Recover / reset | Anyone with email | Regain access without an admin. |
| Dashboard | Signed-in | Confirm session; no business data. |
| Items | Signed-in | Create/list shared notes; change only what you own (or all if admin). |
| Settings | Signed-in | Keep identity current or leave the product. |
| Admin | Superuser | Provision, disable, promote, or remove people. |
| Email | System | Deliver reset and (optional) new-account passwords. |

Private routes under `backend/app/api/routes/private.py` exist only when `FASTAPI_ENV=development` for tests — not a product flow.

## What this is not (yet)

No bookmarks, no read/unread flags, no per-user item visibility, no comments. List items is a **site-wide** catalog. If the assignment is "read status and bookmark," this template is the auth + CRUD chassis those features should hang on: likely extra columns or a join table from `User` to `Item`, plus UI on the Items table — not a new app.
